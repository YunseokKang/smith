# 아키텍처 초안

Python 3.11+를 골격의 구현 언어로 선택했다. 아래 DB·검색·어댑터 구성은 설계 제안이며
외부 연동 구현이나 검증을 완료했다는 뜻이 아니다.

## 계층

1. 입력: 토스 조회 어댑터 / JSON importer / 이후 Hermes 조회 어댑터.
2. 정규화·저장: 원천 식별, 중복 제거, 거래/시점별 평가/버전 이력.
3. 계산: 순자산, 현금흐름, 집중도, 조달 비용, 목표 시나리오.
4. 근거: 금리·시황 공급자와 문서 검색. 발표 시점·관측 시점·출처를 보존.
5. 자문: 비식별 allowlist payload + 계산 결과 + 검색 근거 → Claude Code headless.
6. 출력: CLI 응답, 보고서 미리보기, 명시적 발행, 스케줄러, Gmail delivery.

CLI와 향후 앱은 동일한 application service를 호출한다. 웹 서버를 지금 만들 필요는 없다.
`src/smith/ports.py`는 초기 의존성 경계를 표현하는 Protocol이다.

## 저장소 및 RAG

PoC 원장은 표준 라이브러리 `sqlite3`로 구현했다(`src/smith/ledger.py`, 기본 `data/smith.db`).
선택 이유: 의존성 없음, 단일 사용자 규모, 파일 하나로 백업 가능, transaction 지원.
배포 환경과 동시 실행 요구가 확정되면 재검토한다.
원장은 record revision을 추가만 하는 구조다. 공통 열(ID, kind, owner, source, status, 시각,
revision)은 컬럼으로, 종류별 필드는 정규화된 JSON 텍스트로 저장해 계약 확장 시 migration을 줄인다.
가져오기는 `BEGIN IMMEDIATE` transaction으로 직렬화하며, 스키마 버전은 `PRAGMA user_version`으로 관리한다.
스키마 생성·migration은 쓰기 경로(`import`, `toss sync`)에서만 한다. 미리보기와 조회는 원장을
읽기 전용(`mode=ro`)으로 열고, 구버전 스키마면 메모리 사본을 migration해서 읽는다. 파일은 바꾸지 않는다.
스키마 v2는 순자산에 넣지 않는 참고 지표(매수 가능 금액, 환율)를 담는 `observations` 표를,
v3는 공급자 동기화 시도의 성공·실패를 남기는 `sync_runs` 표를 추가했다.

## 계산 (2단계, `src/smith/summary.py`)

`smith summary`는 원장만 읽어 결정적으로 계산한다. LLM은 이 수치를 계산하지 않는다.
- 기준 통화 KRW. 환산은 `as_of`·`known_at` 이전의 최신 `fx_mid_rate` 관측값을 쓴다.
  환율이 없는 통화의 자산·부채는 합계에 넣지 않고 "미환산"으로 분리해 요약을 불완전으로 표시한다.
- 가계 전체를 합산하되 소유자별 순자산도 따로 보인다(법적 명의에 따라 세금·대출 판단이 달라짐).
- 순자산 = 활성 자산 평가액 − 활성 부채 잔여 원금. 보험 보장액, 매수 가능 금액, 마이너스통장 한도는 제외.
- 자산 배분: 자산 유형·계좌 유형·통화·유동성별 금액과 비중.
- 월 현금흐름: `as_of` 날짜에 유효한 반복 흐름을 월 단위로 환산(분기 ÷3, 연 ÷12, 곱셈 대신 나눗셈).
  `internal_transfer`는 수입·지출과 분리하고, 1회성 흐름은 향후 12개월 예정 항목으로 따로 보인다.
- 대출 이자 추정: 연결된 부채의 잔여 원금 × 연이율 ÷ 12. 추정치로 표시한다.
- 데이터 신선도: 원천별 기준 시각 범위. 수동 90일, API 7일, 환율·매수 가능 금액 7일을 넘으면 경고한다.
  마지막 동기화 실패가 마지막 성공보다 늦으면 경고하고, 원천별 마지막 성공·실패 시각을 표시한다.
- 완전성: 환산하지 못해 합계에서 빠진 항목이 있으면 영역(`balance_sheet`, `cash_flow`, `goals`)을
  `incomplete_areas`에 남기고 `complete=false`로 표시한다. 0 이하 환율은 없는 환율로 취급한다.
- 알 수 없는 자산 분류는 중단하지 않고 `other`로 집계하며 경고한다(분류 변경 정책).
- `--json`은 금액을 문자열로 내보낸다. 5단계 LLM payload의 입력이 된다(비식별화는 5단계에서 추가).
잔고·현금흐름·거래는 구조화된 DB에 저장한다. RAG는 약관·상품 문서·외부 자료·과거 자문을
검색하는 데 사용하며 수치의 원장으로 사용하지 않는다. 문서가 적으면 전문 검색부터 시작해
필요할 때 임베딩 검색을 추가한다. 출처, 문서 버전, 유효 기간과 인용 위치를 보존한다.

## 근거 (4단계, `src/smith/evidence.py`)

1차 범위는 한국·미국 금리다. 2026-10-04 실제 API로 코드와 응답 형식을 확인했다.
- ECOS `StatisticSearch`(일별 `D`): 기준금리 `722Y001/0101000`, 국고채 3년 `817Y002/010200000`,
  10년 `817Y002/010210000`, CD 91일 `817Y002/010502000`, 원/달러 매매기준율 `731Y001/0000001`.
  오류와 빈 결과는 HTTP 200 안의 `RESULT.CODE`로 온다(`INFO-200`은 데이터 없음).
- FRED `series/observations`: `DFEDTARU`, `DFF`, `DGS2`, `DGS10`, `MORTGAGE30US`. 결측은 `"."`이며 0이 아니다.
  `realtime_start`는 FRED 실시간 기간의 시작일이지 발표일이 아니므로 발표일(`published_on`)은 비워 둔다.
- 설정한 시계열은 모두 필수다. 하나라도 관측값이 없으면 그 공급자 전체를 `missing-series:<id>` 실패로
  기록하고 저장하지 않는다(이전 값이 새로 확인된 것처럼 보이지 않도록).
- `retrieved_at`은 응답을 모두 받은 뒤의 시각이다(동기화 시도 시각과 분리). 기존 값 읽기·비교·삽입은
  `BEGIN IMMEDIATE` 하나 안에서 해 동시 실행에서도 같은 값이 두 번 들어가지 않는다.
- 원장 v4 `evidence_points`: 관측일·값·발표일·조회 시각. 값이 바뀐 경우에만 새 행을 추가하므로
  공급자가 과거 값을 수정해도 이전 보고서의 근거를 `known_at`으로 재현할 수 있다.
- 공급자 하나가 실패해도 다른 공급자는 저장한다(누락이 자산 오판으로 이어지지 않으므로). 결과는 `sync_runs`.
- 키는 OS 자격 증명 저장소(`smith.ecos`, `smith.fred`)에 두며 URL에 실리므로 URL·원본 오류를 출력하지 않는다.
- `smith evidence show`: 최신 값, 약 3개월·12개월 전 대비 변화(기준점이 2주 넘게 떨어지면 미표시),
  관측일, 출처, 오래됨(일별 10일, 주간 14일) 표시.
- 공식 발표문(`src/smith/announcements.py`, 원장 v5 `announcements`): Fed 통화정책 보도자료,
  한국은행 총재 기자간담회(`B0000169`)·금통위 의사록(`B0000245`) RSS의 제목·링크·발표 시각만 저장한다.
  피드는 신뢰하지 않는 외부 데이터다. 2MB 제한, 발행 기관 도메인의 https 링크만 허용(파싱할 수 없는 링크는
  해당 항목만 버림), 제목은 제어·폭 없는·방향 제어 문자와 유니코드 줄 구분자를 제거한 뒤 300자로 자르고,
  어떤 내용도 지시로 해석하지 않는다. 제목이나 발표 시각이 바뀌면 새 버전으로 쌓아 `known_at` 재현을 지원한다.
  본문은 5단계에서 필요할 때 가져온다.
  한국은행 통화정책방향 결정문 게시판의 RSS 주소는 확인하지 못해 추측하지 않았다.
- 개인 자산 관련성(`src/smith/relevance.py`): 원장에서 변동금리 부채, 원화 현금·예금, 달러 자산,
  주식·구성 미상 증권, 부동산, 만기 있는 임대보증금 반환 의무의 금액·비중을 결정적으로 계산하고
  관련 시계열·피드를 연결한다. 인과 해석은 5단계 자문이 맡는다. 원장이 불완전하면(미환산 등) 결과에
  `complete=false`와 미환산 금액을 담고 자산 대비 비중은 표시하지 않는다(분모가 불완전하므로).
- 일관된 읽기: 요약·노출·`evidence show`는 `ledger.snapshot()` 읽기 트랜잭션 하나에서 읽어,
  중간에 들어온 import가 분자와 분모를 서로 다른 시점으로 만들지 않게 한다.
- 모든 외부 HTTP 요청(토스, ECOS, FRED, RSS)은 리디렉션을 따르지 않는다(`src/smith/net.py`).
  따라가면 토스 token이나 URL의 API 키가 다른 호스트로 전달되거나 외부 문서가 공식 출처로 저장될 수 있다.
  3xx는 실패로 기록하고, 출처 주소가 바뀌면 확인 후 코드의 주소를 갱신한다.

## 자문 (5단계)

`smith advise --case portfolio|funding|home [--question] [--show-payload]`.
- 원장 뷰(`src/smith/payload.py`): 한 스냅샷에서 요약·레코드·노출·근거·발표를 읽는다. 레코드 ID는
  A*/L*/C*/G* 별칭으로, 노출은 X*로 바꾼다. 소유자 ID는 `self` 또는 `household_member_*`, 원천 ID는
  경고 안에서 S*로 바꾼다. 사용자 지정 질문에 같은 내부 ID가 있으면 전송 전에 동일하게 치환한다.
  별칭과 실제 레코드 ID의 대응은 로컬 출력에만 쓴다.
  허용한 필드만 보내며 `reason`, 계좌 키, 기관명이 들어간 ID는 보내지 않는다. 종목 심볼은 포트폴리오
  사례에서만 보낸다. 금액은 원 단위 정수 문자열이다.
- 차단(AC-07): 질문과 payload 전체에서 계좌번호·카드번호·주민번호·이메일·전화번호, 명시적으로 표기한
  이름·한/영문 주소 패턴과 저장된 토스·ECOS·FRED 키 문자열을 찾으면 보내지 않고 규칙 이름만 출력한다.
  자격 증명 저장소를 읽을 수 없어도 fail closed한다. 입력은 UTF-8 500,000 bytes로 제한한다.
- 사례별 결정적 계산(`src/smith/cases.py`): 포트폴리오(집중도, 달러 비중, 유동성 개월, 부채 비율, 보험료·
  재량 지출), 긴급 조달(본인 자산의 조달 단계별 금액·누계·부족분, 미실현 손익, 해외주식 양도세 추정 —
  손익 통산, 22%·250만 원 공제는 가정), 주택 이동(기준·유리·불리 시나리오의 필요 자금, 본인 가용액,
  부족분, 배우자 부동산 순자산 포함 시 부족분). 누락 환율·원가는 0으로 바꾸지 않고 관련 합계와 판단을
  `null`로 전파한다. 현금흐름은 기준일에 활성인 반복 항목만 쓰고 주택의 본인 가용액에는 본인 흐름만
  반영하며, 원금 상환 추정은 해당 주택 담보대출의 지급액과 이자만 쓴다. 가정값은 모두 결과에 남긴다.
- headless 경계(`src/smith/adviser.py`, Claude Code 2.1.195에서 확인): 네이티브 `claude.exe`를 직접 실행
  (`.cmd` 래퍼는 cmd.exe 인자 해석 때문에 실행 거부), 질문·payload는 stdin, `--tools ""`, `--safe-mode`,
  `--no-session-persistence`, `--system-prompt`, `--output-format json`, `--json-schema`,
  `--max-budget-usd`(기본 1.00), 기본 모델 `opus`. 빈 임시 작업 디렉터리, 환경변수 허용 목록,
  `SMITH_HEADLESS=1`(이 값이 있으면 `smith advise`가 거부해 재귀 실행을 막는다), 300초 제한, 출력 1MB 제한.
- 출력 검증: CLI에는 최소 스키마를 넘긴다(길이·최대 개수·추가 필드 제약이 있으면 실제
  payload에서 `error_max_structured_output_retries`가 났다). 받은 뒤 알 수 없는 필드는 버리고 길이·개수·
  타입을 엄격히 검증하며, refs 필드뿐 아니라 본문에 존재하지 않는 참조를 쓰면 거부한다. 실패 시 세부
  정보는 필드 경로·참조 이름·CLI 결과 subtype만 출력한다.
  5단계는 자유 서술에 나온 모든 숫자가 계산 결과에서 왔는지까지 기계적으로 대조하지는 않는다. 프롬프트로
  제한하고 있으며, 숫자 출처 검증기는 6단계 보고서 설계(`docs/report-design.md` §5)에 제안으로 남아 있다.
- Hermes 운용 자산(`managed_by=hermes`)은 직접 매각·변경을 권하지 않도록 지시하고, 조달 단계에서도
  뒤쪽에 둔다.
- 기록(원장 v6 `advice_runs`): 질문, stdin으로 보낸 것과 동일한 payload 원문과 해시, 프롬프트 버전,
  모델, 비용, 결과 또는 오류. 성공 결과를 기록할 수 없으면 화면에도 자문을 내보내지 않는다.
- 2026-10-04 검토 전 구현으로 실제 데이터의 세 사례가 모두 성공했다(사례당 약 $0.4~0.55).
  검토 수정과 advice-v4 문체 변경 뒤에는 비용이 드는 실제 호출을 다시 하지 않았고 단위 테스트로 경계를 검증했다.

## 메일 발송 (6단계, `src/smith/gmail.py`)

Gmail API, 권한은 `gmail.send` 하나(메일함 읽기 없음). 2026-10-04 공식 문서로 확인.
- 로그인: 데스크톱 앱 OAuth, 루프백(`http://127.0.0.1:<임의 포트>`) + PKCE(S256) + state 검사, `access_type=offline`.
  OAuth 앱은 프로덕션 게시 상태여야 한다(테스트 상태는 refresh token이 7일 후 만료).
- client ID·secret·refresh token은 OS 자격 증명 저장소(`smith.gmail`)에만 둔다. 다운로드한 client JSON은 로그인 후 삭제해도 된다.
- 받는 주소는 Git 제외 `config/smith.local.toml`의 `[mail] recipient` 하나뿐이다. 모델 출력이나 보고서 내용이 수신자를 바꿀 수 없다.
- 발송 결과: 성공(메시지 ID), 실패(4xx), **결과 미상**(요청 후 응답 유실, 5xx, 또는 성공 상태인데 본문·메시지 ID가
  없는 경우). 결과 미상은 자동 재발송하지 않는다.

## 정기 발행 (6단계, `src/smith/delivery.py`, 원장 v8 `report_runs`)

- 회차: 설정의 요일·시각·시간대(기본 월·목 06:00 Asia/Seoul). 회차마다 행 하나(slot 유일).
- 시간대: 계산의 날짜(현금흐름 시작·종료일, 목표일, 제목 날짜)는 설정 시간대의 `as_of`에서 얻는다.
  월요일 06:00 KST는 UTC로 일요일이므로, 발행·미리보기·자문·요약 모두 현지 시각으로 바꿔 넘긴다. 저장은 UTC.
- 상태 흐름: `building`(선점, 메일 요청 전) → `sending`(요청 직전 커밋) → `sent`·`failed`·`unknown`.
  `sent`·`unknown`·진행 중 회차는 자동으로 다시 보내지 않고, `failed`(명확한 실패)만 최대 3회 재시도한다.
  수동 발행(`send-now`)은 회차를 소모하지 않는다.
- 중단 복구: 30분 넘게 `building`인 실행은 메일 요청 전이므로 `failed`(재시도 가능), `sending`인 실행은 이미
  전달됐을 수 있으므로 `unknown`(자동 재발송 금지)으로 닫는다. `run-due`가 매번 먼저 정리한다.
- PC가 꺼져 회차를 놓치면 다음 실행에서 최신 회차 한 통으로 보내며, 제목에 "지연 발송", 본문에 놓친 회차를
  표시한다. 놓친 회차는 그 보고가 `sent` 또는 `unknown`으로 끝날 때 같은 트랜잭션에서 `merged`로 기록한다.
  명확히 실패하면 놓친 회차는 재시도에 그대로 남는다. 최초 실행은 과거 회차를 소급하지 않는다.
- 직전 발송 이후 결과 미상이거나 재시도를 모두 쓴 회차, 발행 전 동기화에 실패한 데이터는 다음 보고서 상단 안내에
  적는다. `report status`도 중단·미상 상태를 표시한다.
- 비교 기준은 직전 `sent` 보고의 스냅샷 시각이다. 발송 직전에 토스·근거 동기화를 실행하고 반환 코드를 확인한다
  (토스 자격 증명이 없어도 `sync_runs`에 실패를 남긴다. 매도 종목 자동 종료는 하지 않음).
- 실행: Windows 작업 스케줄러가 로그온 상태에서 15분마다 `pythonw -m smith report run-due`를 호출한다(자격 증명
  저장소 접근에 사용자 세션 필요). 동시 실행은 무시(IgnoreNew), 배터리 전환 시에도 중단하지 않는다.
  `pythonw`에는 콘솔이 없으므로 설정 오류·자격 증명 누락·발송 결과·비정상 종료는 `data/report-runs.log`에 남기고,
  회차가 정해진 뒤의 설정 누락은 원장에 `failed`(`setup-*`)로도 기록한다.

## 권한 경계

금융 API 키는 어댑터만 접근한다. 조회 전용 권한을 공급자가 지원하면 우선 사용하고,
미지원이면 명시적으로 허용한 조회 endpoint만 어댑터에서 호출한다.
인증 token 발급의 POST와 주문 POST를 혼동하지 않는다. 주문 기능 자체는 제공하지 않는다.
토스증권 Open API는 scope가 없어 같은 token으로 주문 API도 호출된다. 따라서 토스 어댑터는
`docs/toss-openapi.md`의 허용 목록 밖 요청을 네트워크 호출 전에 거부하고, 이를 테스트로 검증한다.

Claude Code headless 실행은 비밀정보나 운영 DB에 직접 접근할 수 없는 별도 작업 경계에서
수행한다. 범용 shell과 임의 HTTP를 자문 도구로 노출하지 않는다. 실제 CLI 버전의 권한·도구
제한 방식을 공식 문서로 확인한다. `--dangerously-skip-permissions`를 기본값으로 삼지 않는다.
Claude Code에서 Smith 기능을 호출하는 경로와 Smith가 headless 추론을 호출하는 경로를
분리해 자기 자신을 재귀 호출하지 않도록 한다.

LLM이 작성한 텍스트는 발송 대상·스케줄·금융 API 호출을 변경할 수 없다.
메일 수신자는 신뢰된 로컬 설정에서만 읽는다. 로그에는 잔고 원문과 인증정보를 남기지 않는다.

## 스케줄 및 복구

시간대 인식 스케줄러가 설정된 현지 요일·시각을 해석한다. 호스트 로컬 시간대에 의존하지 않는다.
지정 발행 슬롯/요청 ID, 데이터 snapshot ID, 분석 버전, 발송 상태를 저장한다.
수동 보고는 정기 보고의 슬롯을 소모하지 않는다. 재시작 후 missed run 정책은 구현 전에 결정한다.
`enabled=false`가 예시 기본값이다. 실제 설정과 발송 테스트를 완료한 뒤 명시적으로 활성화한다.

## Hermes 후속 연동

초기 계약 후보: portfolio snapshot, positions, cash, trades, performance, strategy explanation.
계좌의 사실과 전략 설명을 분리하고 source account mapping으로 중복을 제거한다.
연동 전까지 Hermes 운용 계좌는 수동 입력으로 관리하며, 연동 시 그 수동 레코드를 종료하고 API 원천으로 대체한다.
수집 시점, 스키마 버전, 부분 실패, 인증을 정의한다. 명령/주문 endpoint와 DB 직접 공유는 피한다.
현재 Hermes API의 경로·구조·인증은 확인하지 않았으며 임의로 고정하지 않는다.
