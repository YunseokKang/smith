# 구현 순서

- [x] 요구사항 기준선과 프로젝트 골격 작성.
- [x] CLI 설정 확인과 안전 기본값 검증.
- [x] 저장소 접근 복구 후 기존 파일·AGENTS.md와 비교, 브랜치 반영.
- [x] Windows 개발 환경(.venv, tzdata) 정비와 테스트 비용 지침.
- [x] 0단계: 토스 공식 명세 확인(인증, 권한, 계좌 식별, 보유 주식, 현금 의미, 환율, 한도).
      결과는 `docs/toss-openapi.md`. 실제 계좌 대조는 3단계.
- [x] 1단계: JSON importer, SQLite 원장, 이력·멱등성·종료·정정, 미리보기(AC-02).
      실제 데이터로 부분 수정·종료·정정 흐름을 확인하면 AC-02를 완료로 본다.
- [ ] 2단계: decimal 기반 계산과 `smith summary`: 순자산, 자산 배분, 유동성, 현금흐름,
      기준 시점·누락 표시, 내부 이체/평가 변경 분리(AC-05).
- [ ] 3단계: 토스 조회 어댑터(허용 목록, token 캐시, snapshot 모드), 앱 대조(AC-01).
- [ ] 4단계: 시황 수집과 문서 검색, 출처·시점·관련성 검증(AC-04, AC-08).
- [ ] 5단계: 비식별 payload와 headless LLM 실행 경계, 세 질문의 자문(AC-03, AC-07).
- [ ] 6단계: 보고서 생성, Gmail 연결, 설정 가능한 스케줄·수동 발행·장애 복구(AC-06).
- [ ] 이후 Hermes 조회 API 연결 및 전용 앱.

테스트는 단계별 실제 위험에 맞춘다. 첫 외부 테스트는 조회만 수행한다.
실제 메일 발송 테스트는 수신자를 설정한 뒤 명시적으로 실행한다.
골격 검증 성공을 PoC 완료로 표현하지 않는다.
