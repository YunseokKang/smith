# Smith 요구사항

상태: 요구사항 기준선 v0.1 / 2026-09-27
이 문서는 사용자와 합의한 내용을 기록한다. 기술 선택 제안은 별도로 표시한다.

## 1. 목적과 역할

Smith는 예·적금, 연금, 주식, 부동산, 보험, 부채, 현금흐름을 종합적으로 이해하고
개인 재무 목표에 맞는 자문을 제공한다. Hermes는 별도의 fund manager다.
Smith는 자산을 거래하거나 대출을 신청하지 않는다. 금융 실행은 별도 에이전트의 역할이다.
자체 DB 저장, 보고서 생성, 사용자에게 보고서 발송은 허용되는 운영 동작이다.

Hermes backend는 현재 사용자의 컴퓨터에서 24/7 실행 중이다.
Smith의 실제 배포 위치와 Hermes의 구체 API 계약은 아직 확인하지 않았다.
이 프로젝트 골격은 실제 외부 계좌나 Gmail에 연결되어 있지 않다.

## 3. 핵심 사용 사례

### UC-01 포트폴리오·현금흐름 유지 또는 변경

질문: 현재 투자 포트폴리오와 현금흐름을 유지해야 할까, 바꿔야 할까?

- 현재 자산 배분, 통화·종목·산업 집중도, 유동성, 예정 지출과 목표를 파악한다.
- 거시경제·정치·경제·기술 변화 중 해당 자산에 실제로 관련 있는 변화를 연결한다.
- 유지/부분 조정/큰 폭 조정 등 의미 있는 대안과 기회비용·하방 위험을 비교한다.
- 성향에 부합하는 추천안, 근거, 재검토 조건을 제시한다.

### UC-02 긴급 1억 원 조달

질문: 1억 원을 급하게 마련하려면 무엇이 가장 합리적인가?

- 필요한 날짜와 사용 목적, 인출 가능액, 결제·인출 소요일을 확인한다.
- 현금 사용, 자산 매각, 예·적금 해지, 대출, 혼합안을 비교한다.
- 세금·수수료·중도해지 비용·이자·상환 재원·장기 목표 영향을 계산한다.
- 대출 가능 여부와 금리는 확인된 조건과 가정을 구분한다. 확정 승인으로 표현하지 않는다.
- 금리 상승/자산 하락/소득 감소 시의 부담과 대안을 설명한다.

### UC-03 3년 후 30억 원 주택 이동

질문: 3년 후 30억 원짜리 집으로 이사하려면 어떻게 자금을 마련할까?

- 현재 순자산, 저축 가능액, 기존 주택 처분, 부채·임대보증금 반환 등을 반영한다.
- 취득·처분·이사 비용, 향후 주택가격·수익률·금리 가정을 분리한다.
- 기준/유리/불리한 시나리오별 필요 자기자본·부족분·필요 저축을 제시한다.
- 기한이 정해진 자금과 장기 성장 자금을 구분한다.

위 금액과 기간은 사용자가 제시한 자문 사용 사례다. 실제 자산 보유액으로 저장하지 않는다.
토스만으로 알 수 없는 항목은 JSON 입력 또는 질문으로 보완하고, 불완전한 답임을 표시한다.

## 4. 답변 및 보고서 계약

자문은 추천 판단 → 개인 재무·외부 근거 → 대안별 비용/위험/유동성/장단점 → 판단 변경 조건
→ 데이터 기준 시점·누락·가정 순으로 제공한다. 한국어는 자연스럽고 명확하게 작성한다.
투자 수익률이나 미래 가격을 확정값처럼 말하지 않는다.

Smith는 세계 최고 수준의 프라이빗 뱅커로서 고객에게 보고한다. 친근하되 전문적이고 신뢰를 주는 격식체
("~습니다", 호칭 "고객님")를 쓴다. 독자는 금융 전문가가 아니다(2026-10-04 합의). 정보 나열 대신 무엇을 알아야 하는지, 무엇이 중요한지,
왜 중요한지를 전달한다. 큰 그림(한 줄 결론, 핵심 3가지)부터 세부로 들어가고, 난도 높은 금융 용어는
나올 때마다 그 자리에서 풀어 쓰며, 예시와 생활 단위 숫자를 적극 활용한다. 중학생도 이해할 수 있는 말로 쓰되
핵심은 빠뜨리지 않는다. 세부 원칙과 보고서 구조는 `docs/report-design.md`.

정기 보고서에는 직전 보고와의 자산 변화, 현금흐름, 주요 시황과 개인 영향,
검토할 선택지 및 다음 확인 사항을 포함한다.
자산 변화는 입출금, 투자 손익, 환율, 수동 평가 변경으로 가능한 범위에서 분해한다.
첫 보고서는 기준선으로 표시하며 과거 변동을 만들어내지 않는다.
월/목 서로 다른 편집 형식은 제안일 뿐이며 확정 요구사항이 아니다.

- 정기 일정: 월~토 06:00, Asia/Seoul, 요일마다 다른 주제(`[reports.editions]`). 코드 수정 없이 설정으로 변경.
- 즉시 생성/미리보기와 즉시 발행/발송을 구분한다.
- 수신 주소·발신 방식·인증은 실제 연결 단계에서 설정한다.
- 실패 시 상태를 기록하고 제한적으로 재시도하며 동일 발행의 중복 전송을 억제한다.
- 이메일 제공자가 발송을 수락했으나 응답이 유실된 경우는 '상태 불명'으로 기록하고
  무조건 재전송하지 않는다. 정확히 한 번 전달을 보장한다고 주장하지 않는다.

## 5. 데이터 품질·보안

- 안정적인 owner/account/asset ID, 원천, 기준 시점, 수집 시점을 기록한다.
- 통화와 원화 환산을 분리하며 환율 출처와 기준 시점을 보존한다.
- 금액은 decimal 또는 정수 최소 화폐 단위로 처리한다. float로 금액을 합산하지 않는다.
- JSON 재입력은 멱등적으로 처리한다. 변경 이력, 실제 변동, 과거 오류 정정을 구분한다.
- 평가액과 즉시 사용 가능한 금액을 구분한다. 보험 보장액을 순자산에 더하지 않는다.
- 내부 계좌 이체를 수익으로 계산하지 않고, Hermes와 원계좌 자산을 중복 합산하지 않는다.
- 이름·계좌번호·주소·이메일·인증정보는 LLM payload에서 제외한다.
- 자유 텍스트 메모의 개인정보도 검토/제거한다. 필드명 필터만으로 해결됐다고 간주하지 않는다.
- 외부 문서는 근거 자료로만 취급한다. 문서의 지시가 실행 권한이나 수신자를 바꾸지 못한다.
- LLM은 금융기관 키를 갖지 않으며 허용된 조회 도구만 사용한다.
- 조회 실패, 부분 수집, 오래된 값은 별도 상태로 남기고 0원으로 대체하지 않는다.

## 7. 범위 밖 및 미결정 사항

범위 밖: 매매, 송금, 대출 신청, 보험 가입/해지, Hermes 운용 지시, 첫 버전의 전용 앱,
첫 버전의 한국투자증권 자동 연동. 긴급 변화의 별도 수시 알림은 아직 미확정이다.

결정(2026-10-04): 실행 환경은 사용자 PC(Windows, 월·목 06:00에 켜져 있음). 메일은 Gmail API(OAuth,
발송 전용 `gmail.send` 권한)로 사용자 본인 Gmail 계정에서 보낸다. 계정·수신 주소는 Git 제외 로컬 설정에만 둔다.
PC가 꺼져 정기 발행 시각을 놓치면 건너뛰지 않고, 다시 켜졌을 때 지연 발송임을 표시해 보낸다.
금리 근거는 ECOS·FRED, 원장은 SQLite. 자산 입력값은 원장에 입력됨.

미결정: 시황 데이터 공급자 확대와 비용, 허용할 데이터 지연 및 호출 예산, 예외 시 보고를 중단할지 부분
발행할지, 비상자금·부채 허용 수준, 문서 검색 엔진 선택, 최종 에이전트 명칭.
토스 인증·권한·rate limit·지원 필드는 개발 시 공식 문서와 실제 계정으로 검증한다.
